# 万歩計タウン 要件定義書

**バージョン**: 2.3
**日付**: 2026-08-10

---

## 1. 目的

実際の歩行データをゲームに変換し、体重・速度を考慮した「移動エネルギー」を蓄電池に蓄え、
その電気で夜の地球儀に灯りをともしていく放置ゲームを作る。

---

## 2. コアコンセプト

- 現実の歩行 → ゲーム内資源
  - 歩数 + 移動スピード + 体重 → 「移動エネルギー」を算出
  - エネルギーは蓄電池に蓄積
- 蓄電池 → まちの発展（地球の灯り）
  - 蓄電池が満タンになるとストックされ、まち画面で消費して電力を投入する
  - 投入するたびに発展度が上がり、真っ暗な地球儀に街明かりが少しずつ広がっていく
    （見た目は NASA Black Marble 夜間光画像を球面投影した地球儀。詳細は
    `ai-implementation-spec.md` 4.8 節）
- 放置ゲーム寄り
  - 歩くだけで自然にエネルギーが溜まる
  - プレイヤーは「満タン蓄電池をいつ投入するか」を楽しむ

---

## 3. 主要要件

### 3.1 入力・計算
- 体重・歩行速度・発電変換係数を設定可能
- スマホから歩数を取得（iOS: HealthKit / Android: ハードウェアセンサー）
- GPS による歩行速度の計測（設定画面）
- 移動エネルギーを計算し蓄電池に蓄積

### 3.2 まちの発展システム（地球の灯り）
- 蓄電池満タン分を消費して電力を投入する（現行UIは種類選択なしの単一操作、
  ストック消費と発展更新は単一操作としてまとめられ連打しても安全）
- 発展度（投入回数の合計）に応じて地球儀の街明かりが見た目として広がっていく
  （暗い地球→…→軌道から見た地球。発展度の数値そのものはCompanionScreenに表示しない）
- 最終発展段階到達後はきらめきタイムの視覚演出（回数のテキスト表示はしない）
- 直近の投入からの経過時間で地球儀の色味に薄いムードティントがかかる
  （きげんのテキスト表示はしない）
- まちに名前を付けられる（AppBarのタイトルに表示）

> 「げんきの素」「おもちゃ」による追加効果（蓄電池容量アップ・発電効率アップ）は
> 内部実装として残っているが、現行UIからは選択できず到達不能
（詳細は `ai-implementation-spec.md` 5.1 節）。

### 3.3 進行
- 日ごとの歩数・発電量記録（履歴画面）。全履歴クリアはまちの発展状況
  （発展度・蓄電池・累積発電量・ストック）も初期状態に戻す（個別の1日削除は戻さない）
- なつき度・愛着スコアは内部指標として算出され続けるが、CompanionScreenには表示しない
- 時間帯・天気・季節の背景演出（設定でオフ可）。ただし時間帯パレットの仕組み自体は
  地球儀の見た目に反映されていなかったため撤去済み（天気・季節パーティクルは維持）
- スクリーンショットモード（セッション限り）

### 3.4 非機能要件
- 完全にオフラインで動作
- データは端末内に保存（SharedPreferences）
- クリア条件なし（無限育成型）

---

## 4. スコープ

**実装済み**
- 体重・速度・発電係数の設定
- iOS / Android からの歩数取得
- エネルギー計算・蓄積・満タンストック
- 電力投入（単一操作、ストック消費と発展更新をアトミックに実行）と発展段階（地球の灯り）反映
- 実績・履歴画面（全履歴クリアはまちの発展状況もリセット）
- GPS 歩行速度計測
- 履歴削除後の再同期による歩数・発電量の二重加算防止
- さかのぼり同期の冪等化（複数日の処理中に一部失敗しても、失われず・二重加算もされない）
- HealthKitプラグイン例外の統一的なハンドリング
- 配布バージョン（pubspec.yaml）と設定画面表示の一元化

**将来検討**
- なでる以外のミニアクション（芸を見せる等）
- 難易度プリセット
- オンライン機能
- 「げんきの素」「おもちゃ」効果の UI 復活（`feedAuto` は未使用コードとして 2026-08-08 に削除済み）

---

## 5. 成功基準

- アプリをインストールして歩数を取得できる
- 歩行でエネルギーが蓄積し、満タン蓄電池で相棒が育つ
- データが端末に保存され、再起動後も残る
