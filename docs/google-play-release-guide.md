# Google Play リリース手順（万歩計タウン）

最終更新: 2026-08-10

HTML版: [google-play-release-guide.html](google-play-release-guide.html)（GitHub Pages公開後は `https://fukudak.github.io/pedometer-town/google-play-release-guide.html`）

iOS側の手順は [release-procedures.md](release-procedures.md) を参照。この文書はGoogle Play（Android）のみに絞った手順書。

---

## 0. 事前確認（最優先）

このアプリはすでに署名鍵を生成済み。

```
android/upload-keystore.jks
android/key.properties
```

- **この2ファイルを失うと、Play Store公開後に同じアプリの更新版を二度と出せなくなる。**
- まだ安全な場所（パスワード管理ツール、暗号化した外部ドライブ等）にバックアップしていなければ、今すぐバックアップする
- `key.properties` にはキーストアのパスワードが平文で書かれている。このファイル自体の取り扱いに注意する
- どちらも `.gitignore` 済みでリポジトリにはコミットされない

Application ID（Android）: `com.pedometertown.pedometer_town`

## 1. プライバシーポリシーを公開する

Google Playの審査には公開されたプライバシーポリシーURLが必須。

1. ブラウザで `https://github.com/fukudak/pedometer-town/settings/pages` を開く
2. "Build and deployment" の **Source** を `Deploy from a branch` にする
3. **Branch** を `master`、フォルダを `/docs` に設定して **Save**
4. 数分待つと `https://fukudak.github.io/pedometer-town/privacy.html` でプライバシーポリシーが公開される
5. 公開されたURLにアクセスして表示を確認する

---

## 2. Google Play Console に登録する（初回のみ）

1. `https://play.google.com/console/signup` にアクセス
2. Googleアカウントでログインし、登録料 $25 を支払う（デベロッパーアカウント全体で1回のみ）
3. デベロッパー名・連絡先情報を入力して登録を完了する

---

## 3. アプリを新規作成する

1. Play Console ダッシュボードで **アプリを作成**
2. 以下を入力する
   - アプリ名: `万歩計タウン`
   - デフォルトの言語: 日本語
   - アプリ/ゲーム: アプリ
   - 無料/有料: 選択

---

## 4. ストアの掲載情報を入力する

左メニューの **ストアの掲載情報** で入力する。

| 項目 | 内容 |
|---|---|
| 簡単な説明（80文字以内） | 歩いて発電し、夜の地球に灯りをともす万歩計アプリ |
| 詳細な説明 | 下記「アプリの説明文（下書き）」を参照 |
| アプリアイコン | `assets/app_icon.png` から書き出したストア用アイコン |
| スクリーンショット | 手順5で撮影したもの |
| カテゴリ | 健康/フィットネス |

### アプリの説明文（下書き）

> 歩くだけで発電して、夜の地球に街の灯りをともそう。
>
> 「万歩計タウン」は、毎日の歩数をエネルギーに変換し、そのエネルギーで夜の地球儀に街明かりを広げていく歩数連動の放置ゲームです。
>
> 【主な機能】
> - 歩数をエネルギー(Wh)に変換して蓄電池に蓄積
> - 満タンになった蓄電池をストックし、まち画面で「投入」して地球の灯りを広げる
> - 発展度に応じて夜の地球儀の街明かりが段階的に増えていく（暗い地球 → 軌道から見た地球）
> - 地球儀は自転し、ドラッグで手動回転も可能
> - GPSで実際の歩行速度を計測し、設定に反映
> - 過去の歩数・発電量の履歴を確認・削除可能
> - 体重・歩行速度・発電変換係数・まちの名前をカスタマイズ
>
> 歩くモチベーションを、夜の地球を育てる時間に変えてみませんか？
>
> 【ご利用にあたって】
> - 歩数の取得には、iOSはHealthKit、Androidは歩数センサーを使用します
> - 位置情報は歩行速度の計測時のみ使用し、保存されません
> - 取得したデータは全て端末内に保存され、外部へ送信されることはありません

（`docs/store-listing.md` と同内容）

## 5. スクリーンショットを準備する

1. 実機または `flutter run` でシミュレータ／エミュレータを起動してアプリを撮影する
2. 最低4〜6枚を推奨。以下の画面が対象
   - ホーム画面（蓄電池・歩数・発電量が表示された状態）
   - まち画面（地球儀に街明かりがともった状態・累積発電量表示）
   - 履歴画面
   - 設定画面
   - 遊び方画面
3. Androidは単一サイズで概ね問題ないが、複数デバイスのスクリーンショットがあると印象が良い

## 6. アプリのコンテンツ（ポリシー）に回答する

左メニューの **ポリシー → アプリのコンテンツ** で以下に回答する。

| 項目 | 回答内容 |
|---|---|
| プライバシーポリシー | 手順1で公開したURL |
| 広告 | なし（広告を含まない） |
| コンテンツのレーティング | アンケートに回答。健康フィットネス系アプリとして概ね「全年齢対象」になる想定 |
| データセーフティ | 下記参照 |

### データセーフティフォームの回答方針

- **収集する情報**: 歩数、位置情報（速度計測時のみ）、体重・歩行速度・発電変換係数などの設定値
- **用途**: アプリ機能の提供のみ
- **第三者への共有**: なし
- **送信の有無**: 端末内保存のみのため「データを収集しているが外部に送信していない」を選択
- **暗号化**: 送信自体が発生しないため該当なし
- **ユーザーによる削除可否**: 可能（アプリ内の履歴画面から削除でき、アンインストールで全データ削除）

## 7. Androidビルドを作成する

```bash
flutter build appbundle --release
```

- 生成物: `build/app/outputs/bundle/release/app-release.aab`
- `pubspec.yaml` の `version:`（例 `1.0.0+1`）がそのままストアのバージョン表示・ビルド番号になる（`package_info_plus` 経由でアプリ内バージョン表示にも使われる。詳細は [ai-implementation-spec.md](../doc/ai-implementation-spec.md) 1章）
- 新しいバージョンをリリースするたびに `version:` の値（特に `+` の後のビルド番号）を必ず増やしてから再ビルドする

---

## 8. 内部テスト → 製品版リリース

1. Play Console 左メニュー **テスト → 内部テスト**（最初は内部テストを推奨）
2. **新しいリリースを作成** → 手順7の `.aab` をアップロード
3. リリースノートを入力して保存 → 確認 → 公開
4. 内部テストのテスターとして自分のGoogleアカウントを登録し、テストリンクからインストールして動作確認する
5. 問題なければ **製品版** リリースを作成し、同じ `.aab`（または新しいビルド）を使って審査に提出する

---

## 9. 審査提出後

- 初回審査は数時間〜数日程度かかる
- ポリシー違反の指摘があれば、該当箇所を修正して再提出する

## 困ったときに確認する箇所

| 問題 | 確認先 |
|---|---|
| Android署名エラー | `android/key.properties` の内容、`android/upload-keystore.jks` の存在 |
| データセーフティ審査の指摘 | `docs/privacy.html` の内容とフォームの回答が一致しているか |
| ビルドが古いバージョンのまま | `pubspec.yaml` の `version:` を更新してから再ビルド（例: `1.0.0+1` → `1.0.1+2`） |
| Kotlin Gradle Plugin の警告 | `health`, `pedometer`, `device_info_plus`, `package_info_plus` が出す非互換警告。現時点ではビルドに影響なし |
